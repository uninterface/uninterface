# Dynamic stacking integration

[Backend reference](README.md) · [API reference](../README.md)

Actual root/popup registration and core-owned ordering.

Follow the [backend stacking rules](../../contracts/dynamic-z-order.md#backend-stacking-rules) when integrating or upgrading a toolkit. Review the assembled CSS and runtime writes, including reused presentation wrappers. Document any retained local ranks and the boundary that contains them.

## Dynamic stacking protocol

Core is the sole rank owner. Backends declare `stacking.dynamic.v1`; application setup requires it. The [contract](../../contracts/dynamic-z-order.md#browser-projection-protocol) defines bands, physical boundaries, transactions and verification limits.

- `useUiZView({ binding?, targets?, host?, self? } = {})` consumes the core outward `UiZViewBinding` from context, or an explicitly supplied binding. It declares the backend's own rendered roots (multiple roots supported; Teleports excluded), or explicit `targets()`, as physical hosts even for passive identities. Initial projection waits until the mount batch has registered parent allocation directives, then selects a containing root from the logical ancestor chain. `host(element)` supplies an explicit physical host where native composition requires one. Nested private backend views do not inherit a consumed binding. It preserves roots and supplies positioning only when the participant is materialized; declaring a host alone adds no z-index or stacking context.
- `UiZViewBinding` is the opaque core binding carried in `zItems`, `zResize`, tab/breadcrumb items and column/card field definitions. Views consume it; they must not mutate its domain, parents, declarations or resolved values.
- `useUiZPart()` supplies a local directive (`mounted`, `updated`, `beforeUnmount`) receiving an optional binding. Apply it to the actual allocation/cell/field root. Passive allocations still declare their physical roots so descendants remain hosted inside their owning scroll region. Declarations are released on removal or binding replacement. `UiLayoutViewBinding.zItems` and `UiRegionLayoutViewBinding.zItems` map allocation names/keys to bindings. `UiLayoutViewBinding.zResize` supplies the local resizer registration. No private rank arithmetic or max-plus-one offsets are permitted.
- `useUiZPopup(target, { source?, topLayer?, observe?, scope?, scopeActive? })` accepts a getter for the actual connected positioning wrapper. It registers in the owning Surface's Floating layer, tracks native creation/removal through DOM/ref updates and retains exit allocation until the target disappears. `scope: true` makes contained submenu registrations children of this popup. KeepAlive deactivation closes/releases popups. It returns `handle`, `prepare(element, native = true)`, `hasNativeAbove()`, `closed()` and `release()`. topLayer accepts a boolean or reactive getter. prepare(element, false) stages the physical target without native opening; hasNativeAbove reports an already-live higher native target through the shared allocator. Changing between native/CSS registration preserves its logical group and descendants. For native popovers call `prepare` before `showPopover`, and `closed` after dismissal (also on failed opening). `observe: false` is only for views that report target changes reactively. Do not register a trigger or inner label in place of its outer positioning boundary. Nested registrations wait for their scoped popup owner to register and use an enclosing registered native popover as their physical host. This keeps outside layout stacking/clipping ancestors from constraining content inside the native top layer and preserves the host through dismissal. A presenter that owns its positioning root directly must register that root, not an ancestor popover.

The shared modal helper registers a new Surface for each session, attaches the dialog before `showModal`, retains it through exit and releases after native close. Its native backdrop realizes the mask; no extra business mask is required. A second modal dominates the first surface including attached popups. Numeric repacking never closes/reopens a modal or moves focus. Unsupported live top-layer reversal is diagnosed.

Register the actual popup positioning wrapper through the shared stacking protocol, coordinating before opening where required. Selection, multi-selection, paginator sizes, menus/submenus, suggestions, tooltips, validation hints, navigation hints and temporal pickers participate. Browser-owned picker UI remains under the user agent’s control. Collection decorations stay within their core-owned outward context so table headers cannot overtake floating choices. Concrete popup targets belong in backend documentation.

Set `scopeActive` false for a branch that forwards popup ownership without rendering its own popup. A permanently empty target with an active scope makes descendant registrations wait for a parent that cannot appear. Lookups from a descendant can return its ancestor's handle. To verify registration, compare `describe(handle).target` with the actual wrapper and check its physical host.

Projection applies an important inline derived value and observes competing toolkit writes; native counters have no authority over managed targets. Host validation rejects unsupported intervening contexts/clipping and observes relevant ancestor class/style/movement changes. A managed logical ancestor is a valid physical boundary. Release restores the prior inline presentation and removes observers. App disposal attempts every release.

Owned popup hosting follows native teleport relocation: a positioning wrapper initially created under the document may later move directly into its owning dialog. The physical host is refreshed for validation and diagnostics while the logical handle and rank remain stable. This does not permit unregistered intermediate transform or clipping boundaries.

Test the actual wrapper, exit/deactivation lifetime, counter attempts, isolated apps and reference updates. DOM wiring and integer comparisons do not prove painted order: use overlap hit-testing, focus/modality and dismissal checks in real browsers.
