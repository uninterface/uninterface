# collectionHeaderLongRow

Import from `@uninterface/uninterface`. Built-in [UiCollectionHeaderAdaptation](../types/UiCollectionHeaderAdaptation.md), named `long-row`. A stable, frozen object; no registration is required.

Search, filters and optional Reset precede the sort row. The action group prefers the filter row's inline-end and aligns to the controls on that row. When it moves beside sorting or to a following row, it aligns to the top. Allocation uses measured native group widths and gaps, with one gap of hysteresis before promoting to an earlier row. Info follows. Controls retain natural width and wrap as needed. Cooperating query fields and buttons align their editor surfaces per line, including with omitted labels. Query filters receive filter-row/inline/single-row context. Search uses the host’s default context: filter-row only outside mobile alongside filters using the default collectionFilterPanel fields presentation; otherwise header-search/inline/single-row, hiding its visible label while retaining its accessible name. Badge/custom filter presentations and sort-only headers do not enable the label. Search, reset and actions then share the available row, with flexible space before actions.

Use as a constant or selector result with [uiCollectionHeaderPresentation](../../strategies/uiCollectionHeaderPresentation.md). It is the default outside the mobile environment. Table/card differences come from supplied controls, not another adaptation. Its view function implements the Vue composition; private backend flow/part components fulfill local allocation, theme spacing and editor alignment. It does not return a layout description. Verify optional-slot omission, action separation, wrapping, identity/focus, and no data requests during layout changes.
